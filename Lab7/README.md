# Lab 7: Fuzz Testing for Input Validation Bugs

## 1. Lab Objective

The primary objective of this laboratory exercise is to apply property-based fuzz testing using **Hypothesis** in Python to discover input validation vulnerabilities in an existing coffee shop data processing application (`processor.py`). Once vulnerabilities are exposed through minimal failing examples generated by Hypothesis, the application code is defensively refactored and re-tested to ensure that all fuzz tests and functional tests pass without crashing.

---

## 2. What Fuzz Testing Is

**Fuzz testing (fuzzing)** is an automated software testing technique that provides invalid, unexpected, malformed, or random data as inputs to a computer program. The program is then monitored for exceptions, unhandled crashes, memory leaks, or failing built-in code assertions. Unlike traditional example-based unit testing—which tests only anticipated inputs chosen by the developer—fuzzing tests edge cases and boundary conditions that humans frequently overlook.

---

## 3. What Hypothesis Does

**Hypothesis** is a modern property-based testing library for Python. Rather than writing test cases with specific individual input values, developers define *properties* that code should always satisfy across broad *strategies* of generated data (e.g., `st.text()`, `st.integers()`, `st.floats()`, `st.none()`, `st.one_of()`).
Key capabilities of Hypothesis include:
- **Broad Exploration**: Generates hundreds of edge-case inputs (empty strings, `None`, Unicode, extreme numbers, special characters).
- **Automated Shrinking**: When a test failure occurs, Hypothesis automatically minimizes the failing input to the simplest possible counterexample (e.g., reducing a 200-character string to `""` or `None`), making root-cause diagnosis straightforward.

## 4. Description of All Three Functions

1. **`lookup_drink_code(code_string)`**:
   - Takes a drink code prefix string (e.g. `"LAT"`, `"CAP"`, `"ESP"`, `"AME"`, `"MOC"`).
   - Extracts the first 3 characters in uppercase and queries a menu price lookup table.
   - Intended to return the base beverage price (`float`).

2. **`calculate_average_shot_cost(pricing_csv)`**:
   - Takes a comma-separated string of shot prices (e.g. `"1.0, 1.5, 2.0"`).
   - Splits tokens by comma, parses them to floats, and computes the arithmetic mean.
   - Intended to return the average espresso shot price (`float`).

3. **`parse_order_modifiers(order_spec)`**:
   - Takes a semicolon-delimited string of modifier specifications (e.g. `"milk:oat;syrup:vanilla"`).
   - Splits tokens by `;`, unpacks each `key:value` pair by `:`, and populates a dictionary.
   - Intended to return a dictionary of modifier key-value mappings.

## 5. Original Application Behaviour

Under standard, ideal interactive inputs (`LAT`, `1.0, 1.5, 2.0`, `milk:oat;syrup:vanilla`), the original script executed without errors:
- Base Price: \$4.50
- Average Shot Price: \$1.50
- Parsed Modifiers: `{'milk': 'oat', 'syrup': 'vanilla'}`

However, the original functions lacked defensive input validation, type checking, or exception handling. Any unexpected input immediately caused fatal crashes.

---

## 6. Bugs Discovered

1. **`lookup_drink_code`**:
   - **`AttributeError` on `None`**: Attempting to call `.upper()` on `NoneType` raised `AttributeError: 'NoneType' object has no attribute 'upper'`.
   - **`KeyError` on Invalid/Empty Strings**: Indexing the dictionary with missing keys (e.g. `""`, `"XYZ"`) raised `KeyError`.
   - **Typo in Price Dictionary**: The dictionary key `"MOc"` contained a lowercase `'c'`, causing `"MOC"` to trigger `KeyError: 'MOC'`.

2. **`calculate_average_shot_cost`**:
   - **`AttributeError` on `None`**: Attempting `.split(',')` on `NoneType` raised `AttributeError: 'NoneType' object has no attribute 'split'`.
   - **`ValueError` on Empty/Malformed String**: `"".split(',')` yielded `['']`, causing `float('')` to throw `ValueError: could not convert string to float: ''`.
   - **`ZeroDivisionError`**: If an empty collection or string was processed, dividing by `len(prices)` resulted in `ZeroDivisionError: division by zero`.
   - **Negative Values / Non-finite floats**: Unchecked parsing allowed negative or NaN values into financial calculations.

3. **`parse_order_modifiers`**:
   - **`AttributeError` on `None`**: Attempting `.split(';')` on `NoneType` raised `AttributeError: 'NoneType' object has no attribute 'split'`.
   - **`ValueError` on Unpack (Too Few Values)**: For empty strings `""` or entries lacking a colon (e.g. `"extra"`), `item.split(':')` returned 1 element, raising `ValueError: not enough values to unpack (expected 2, got 1)`.
   - **`ValueError` on Unpack (Too Many Values)**: For entries containing multiple colons (e.g. `"a:b:c"`), unpacking into 2 variables raised `ValueError: too many values to unpack (expected 2)`.

## 8. Fixes Implemented

The application was defensively refactored in [`processor.py`](processor.py):

1. **`lookup_drink_code`**:
   - Added explicit type and null check: returns `None` if `code_string` is `None` or not a `str`.
   - Strips whitespace and verifies length is at least 3 characters before slicing.
   - Fixed dictionary key casing to `"MOC": 5.00`.
   - Used safe dictionary access `menu_prices.get(code_prefix, None)`.

2. **`calculate_average_shot_cost`**:
   - Validates that `pricing_csv` is a non-null string; returns `0.0` otherwise.
   - Splits by `,`, trims tokens, and safely parses valid numeric floats.
   - Filters out non-finite (`NaN`, `Inf`) and negative prices.
   - Guarantees `len(prices) > 0` before division to prevent `ZeroDivisionError`; returns `0.0` if empty.

3. **`parse_order_modifiers`**:
   - Validates that `order_spec` is a non-null string; returns `{}` otherwise.
   - Trims whitespace and filters out empty tokens (handles trailing semicolons).
   - Requires `:` to be present; uses `item.split(':', 1)` to cleanly handle arbitrary additional colons without unpacking errors.
   - Strips keys and values before adding to the returned dictionary.

4. **`main` CLI interface**:
   - Added graceful fallback printing when an invalid drink code is entered instead of crashing.
